### Correction — "zero failed cards" was overstated
- `paymentRecords` in Jobber's API is NOT a list of money received. August 2026: 1,973 records = 1,143 `JobberPaymentsCreditCardPaymentRecord` + **787 `OtherPaymentRecord` (paymentOrigin UNKNOWN_ORIGIN, no status, no paymentType)**. Those 787 mirror INVOICES, not payments — proof: Western Plaza #15743, $700, entryDate 2026-08-31, is in there and its balance is still the full $700, unpaid and not even due until Sep 30.
- Of the 1,143 real CARD records in August: **1,140 SUCCEEDED, 1 PENDING, 2 REFUNDED, 0 FAILED.**
- `FAILED` IS a valid value — enum is `JobberPaymentTransactionStatus` (IN_DISPUTE / PENDING / REFUNDED / PARTIALLY_REFUNDED / FAILED / DISPUTED / SUCCEEDED) and `transactionStatus` is a queryable field on the credit-card record type. So the query CAN return failures; it returns none.
- **A literal zero decline rate across a full month of recurring card billing is not credible** (industry norm on recurring cards is ~5-15%). Conclusion: a declined autopay charge almost certainly never becomes a paymentRecord at all, so failures are INVISIBLE to this API. Absence of FAILED is not evidence of no failures.
- Therefore the earlier inference — "card on file + past due = never charged, just a toggle" — does NOT hold. It could equally be declining cards. Route to the truth is the Jobber Payments transactions view in the UI (Stripe-backed) via `tool-browser`, or a Stripe-side export.
