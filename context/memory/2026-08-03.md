### 2026-08-07 — one-week exception overlay (the right answer to "reflect the new route")
- Spencer re-cut next week and asked the tool to reflect it. **Checked before acting: the grid still
  matches THIS week (10 divergences, nearly all single-stop spills) but diverges on 55 of 110
  serviced zips for the week of 08-10.** So next week is an EXCEPTION (Cammeron out, Robert
  covering), not a new standing pattern — rewriting `territory-grid-v5.json` from it would have
  corrupted the standing definition `push-week` uses to pull flexible visits onto days.
- Built an **overlay** instead: `make-service-day-sheet.mjs --overlay-week=<monday>` reads that
  week's live OptimoRoute routes, takes each zip's dominant routed day, and shows an exception only
  where it disagrees with the grid. Card now reads e.g. 98391 "Thursdays" + amber "Week of Aug 10-14:
  Friday (Fri, Aug 14) — that week only. Normally Thursdays" + "Other weeks: Thu Aug 20, Thu Aug 27".
  Dates inside the exception week are filtered out of the normal list so the card cannot contradict
  itself.
- `--overlay-week=next` self-resolves to the coming Monday. The cron passes that, so the overlay
  follows the calendar instead of expiring silently. **Flag is mandatory in the job** — without it
  the nightly rebuild wipes the overlay and the office quietly reverts to the standing day for all 55.
- Method note worth keeping: compare the grid against the CURRENT week as well as the target week
  before deciding whether a divergence is a re-cut or an exception. Only the pair distinguishes them.
