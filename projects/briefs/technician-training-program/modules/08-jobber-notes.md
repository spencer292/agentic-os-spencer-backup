# Module 8 — Jobber: The Visit Note

## Why this is a module and not a footnote

The note you write is not paperwork. **It is the instruction that schedules the customer's next
visit.** Nobody re-walks the property to decide when you come back — the office and the
scheduling system read your note and act on it. Write it wrong and a customer with an active
mole waits a month.

That is not hypothetical. In the last five weeks, **22 visits with confirmed activity got no
follow-up instruction at all**, and **six visits where a mole was caught were sent to monthly.**
Every one of those was a real customer who waited.

**The standard in this module is Cory's.** It was not invented for the training program — it
was read off 486 of his real notes. Write yours like his.

---

## 1. The four blocks

Every note has four blocks, in this order. One item per line. Short.

```
1 caught          ← 1. OUTCOME — what happened with the traps that were already there
LA                ← 2. ACTIVITY — one code
3 VOOS boh        ← 3. TRAPS — what is in the ground when you leave
Add visit         ← 4. NEXT ACTION — when we come back
```

A real one, verbatim:

```
2 caught
Pulled 1 VOOS
LA
3 VOOS foh
1 TL boh
Add visit
```

And the other direction — a genuinely quiet property:

```
No moles
No misses
NA
Pulled 1 v
1 v BOH
Monthly
```

---

## 2. Block 1 — Outcome

What happened with the traps that were already in the ground. **First line, every repeat visit.**

| Write | Means |
|---|---|
| `1 caught` / `2 caught` | Moles caught. Always the count. |
| `No mole` / `No moles` | Traps were there, nothing in them. |
| `Missed 1` / `Missed 3` | **A trap got hit and did not hold.** |
| `No misses` | Checked, nothing was hit. Worth writing. |
| `Moved 1` / `Moved 2` | Existing traps relocated. |
| `Pulled 1 VOOS` | Traps removed. |
| `Added 1 TL` | Traps added beyond what was there. |
| `Swapped 1 VOOS for TL` | Trap type changed. |
| `Pulled and closed` | Everything out, job done. |
| `No traps` | Nothing was in the ground when you arrived. |

Stack as many lines as it takes. `1 caught` / `Missed 1` / `Moved 2` is three lines and that's fine.

> **Misses are not a footnote — they are the reason for the next visit.** See §3.

---

## 3. Block 2 — The activity code

One line. One code. No slashes — Cory writes `LA`, not `L/A`.

| Code | Means |
|---|---|
| `NA` | No activity |
| `LA` | Light activity |
| `MA` | Moderate activity |
| `HA` | Heavy activity |

### What actually decides the code

Full reasoning is Module 4 §8. The short version:

**Activity is YES if any one of these is true — fresh sign, a catch, or a miss.**

- **Fresh sign** — loose damp mounds matching the subsoil, soft springy ridges.
- **A catch.** Any number.
- **A miss.** A trap that got hit and didn't hold means a mole was working that run and got
  away. That is activity on its own, with nothing else on the property.

**Old mounds are not activity.** Dried, crusted, grass growing through — that's where moles
*were*. A yard can be covered in old sign and still be an honest `NA`.

> ### The mistake to avoid
> **If you caught a mole or had a miss, the property is not `NA`.**
>
> This is the single most common error in the current notes — 26 notes in five weeks read
> `1 caught` and then `NA` two lines later. It reads as a contradiction because it is one. A
> mole was in that yard *this week*; you have proof in your hand.
>
> Caught something or missed something → the code is `LA` at minimum.

---

## 4. Block 3 — Traps

What is in the ground **when you drive away.** Not what you set — what is there now.

Format: **count + type + location.**

**Types:**
- `VOOS` — Victor Out-O-Sight (also written `v`)
- `TL` — Trapline

**Locations:**

| Code | Means |
|---|---|
| `foh` | front of house |
| `boh` | back of house |
| `roh` | right of house |
| `loh` | left of house |
| `bloh` | back left of house |

Add a plain-English detail when the code isn't enough — this is encouraged, not discouraged:

```
1 TL boh right fence
1 VOOS left rose garden
1 TL main house right walkway
3 VOOS perimeter
```

The next tech on this property has to find your traps. `2 VOOS boh` on a half-acre yard is a
scavenger hunt. `2 VOOS boh right fence line` is an address.

---

## 5. Block 4 — Next action

**This is the line that schedules the customer.** Everything above it is context; this is the
instruction. If it is missing, nothing happens.

### Total Mole Control Program

| What you found | Write |
|---|---|
| Any activity — `LA`, `MA`, or `HA` | `Add visit` |
| A catch, any number | `Add visit` |
| A miss, even with nothing else | `Add visit` |
| `NA`, nothing caught, no misses | `Monthly` |

The activity *level* does not change the answer. `LA` and `HA` both mean `Add visit`. The only
question is activity or none.

> **Do not write `2 weeks`.** It is a retired interval from an older rule and it is still
> appearing in notes — 24 times in five weeks, and it books the customer 14 days out. There is
> no 14-day follow-up anymore. It is `Add visit` or it is `Monthly`.

### The Quick Fix

Quick Fix is a five-week weekly series. It is already weekly by construction, so **most Quick
Fix notes need no next-action line at all** — 84 of Cory's 94 have none, and that is correct.

**When the five weeks are used up and there is still activity, you do not add a visit.** That
is a sales decision — another visit, or moving them to TMCP. Flag it. Say so in the note and
tell the office. Nobody schedules past the series on their own.

### Which product am I on?

Read the **line item on the job**, not the job type. Every Got Moles job says "Recurring,"
Quick Fix included, so the job type tells you nothing.

- `Total Mole Control Program -- Year round protection` / `Total Mole Control Package` → **TMCP**
- `The Quick Fix — One-Month Mole Control Program` → **Quick Fix**

---

## 6. Write it before you leave

Note goes in from the truck, immediately after you set. Not at lunch, not at the end of the
day, not tomorrow morning. You will merge two properties in your head and the note will be
wrong for both.

---

## What good looks like — worked examples

**Caught one, still active:**
```
1 caught
Moved 2
LA
2 VOOS boh
Add visit
```

**Nothing caught, but a miss — this still earns a visit:**
```
Missed 2
Moved 3 added 1 VOOS
MA
3 VOOS boh
1 VOOS foh
Add visit
```

**Genuinely quiet — the only note that goes monthly:**
```
No mole
NA
1 v front left fence line
Monthly
```

**Quick Fix mid-series — no next action needed:**
```
3 VOOS foh
MA
```

## Field checklist — The Note

- ☐ Written from the truck before leaving the property
- ☐ **Outcome** first — caught / no mole / missed / moved / pulled / added, with counts
- ☐ **Misses written down** — `Missed 2`, not left out
- ☐ **Activity code** on its own line — `NA` / `LA` / `MA` / `HA`
- ☐ Code is not `NA` if I caught something or had a miss
- ☐ **Traps** — count + type + location, describing what's in the ground as I leave
- ☐ Location specific enough for the next tech to find them
- ☐ **Next action** — TMCP: `Add visit` for any activity, catch, or miss; `Monthly` only for a
  true `NA`
- ☐ Never `2 weeks`
- ☐ Quick Fix: no next-action line, unless the series is exhausted with activity → flag it
- ☐ Product confirmed from the job's **line item**, not the job type

## Engine note — read before changing this module

The scheduling engine (`projects/briefs/jobber-notes-automation/decide.mjs`) reads **only the
free-text next-action line.** It parses `activity` and `moles` and then never uses them.

That means everything in this module is delivered through Block 4 and nothing else. A perfect
`Missed 3` + `LA` note with no `Add visit` line produces **no scheduling action at all** — the
engine logs `LEAVE` and moves on. That is exactly how the 22 activity-with-no-follow-up cases
happened.

**Recommended fix (route lane, not training):** have the engine *derive* the interval from
product + catch + miss + activity code, and treat the next-action line as a tech override rather
than the sole input. The rules are fully deterministic now, and the note already carries every
input they need — the only reason the schedule depends on one hand-typed line is that nothing
reads the rest.
