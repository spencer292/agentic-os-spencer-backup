## Notes

- **LinkedIn's messaging UI now runs inside a nested same-origin iframe** (`linkedin.com/preload/?_bprMode=vanilla`),
  and the connect modal renders in a **shadow root** on a `div.theme--light` host. Neither is
  reachable from a plain `document.querySelector`, which is why the first passes returned empty
  arrays on a page that visibly had the controls. Reach them via
  `[...document.querySelectorAll('iframe')].find(x=>x.src.includes('preload')).contentDocument`
  and `[...document.querySelectorAll('*')].find(e=>e.shadowRoot).shadowRoot`.
- **`browser/cdp.mjs type` cannot fill either one.** It uses the native `HTMLInputElement.value`
  setter, which does nothing to a contenteditable div and does not reach into a shadow root.
  Text has to go in with CDP `Input.insertText` after focusing the element — helper written this
  session at `scratchpad/insertX.mjs` (takes a JS expression that returns the element).
- The Send button reads `disabled` for a moment after text is inserted. That is a race, not a
  failure — re-read it before concluding the message did not take.
- Extraction technique unchanged and still working — the anchor-map (`a[href*="/in/"]` → innerText)
  returned clean rows on all four hub searches.
- Sales Navigator's "People who can introduce you" panel appeared on Samantha Oldham's profile
  offering Nick plus four others. Worth reading on every prospect from now on; it's better intel
  than the mutual-connection line on the search row.
- Search spend was 4 for the session. The July research did the finding, so nothing was re-searched.
